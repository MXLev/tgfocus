# TGFocus для Windows v0.1.0

Небольшое фоновое приложение в системном трее рядом с часами. Окно настроек можно закрыть: приложение продолжает работать. Полный выход — через значок TGFocus → **«Завершить TGFocus»**. Значок может находиться под стрелкой **`^`**.

Поддерживаемая система — **Windows 11 x64**. Это отдельная Windows-оболочка вокруг общего Telegram-модуля, локальных правил и необязательного ИИ. Версия macOS остаётся самостоятельной.

## Скачать и запустить

**[Скачать TGFocus v0.1.0 для Windows x64](https://github.com/MXLev/tgfocus/releases/download/windows-v0.1.0/TGFocus-Windows-v0.1.0-x64.zip)** · [страница релиза, SHA-256 и отчёт проверки](https://github.com/MXLev/tgfocus/releases/tag/windows-v0.1.0).

1. Скачай `TGFocus-Windows-v0.1.0-x64.zip`; контрольная сумма находится рядом на странице релиза.
2. Полностью распакуй папку в постоянное место, например `%LOCALAPPDATA%\Programs\TGFocus`.
3. Запусти **`TGFocus.exe`** из распакованной папки. Не запускай из ZIP и не отделяй EXE от `_internal` и `helper` — они содержат Qt, Python и Telegram-модуль.
4. Найди значок в трее и открой настройки. При первом запуске фильтр выключен; автоматизация и ИИ тоже выключены.

Отдельные Python, Qt и инструменты разработчика для готового пакета не нужны. Выпуск **не подписан доверенным сертификатом издателя**; Windows SmartScreen может предупредить о неизвестном приложении. См. [политику подписи](CODE_SIGNING_POLICY.md), [приватность](PRIVACY.md) и [удаление](WINDOWS-UNINSTALL.ru.md).

Это переносимое приложение без установщика: отдельной записи в «Установленных приложениях» нет. Системные разрешения уведомлений настраиваются в **Система → Уведомления**, а автозагрузка — отдельно. Пошаговые действия приведены ниже.

Иконка TGFocus встроена в оба EXE и используется в окне, меню «Пуск» и уведомлениях. Для баннеров в `_internal/assets` поставляется отдельный PNG; сохраняй всю папку программы вместе. Исходная геометрия и генерация PNG/ICO находятся в [source/Windows/icons.py](source/Windows/icons.py).

Бесплатная доверенная подпись возможна через программы с рассмотрением проекта или публикацией в Microsoft Store. Она пока **не подключена**. Подготовленные данные заявки, условия и действия владельца описаны в [WINDOWS-SIGNING.ru.md](WINDOWS-SIGNING.ru.md). Самоподпись не убирает предупреждения на чужих компьютерах.

При запуске TGFocus создаёт или обновляет **свой ярлык в меню «Пуск»** для текущего пользователя. В ярлыке и отправителе уведомлений используется один идентификатор приложения — это позволяет Windows распознавать TGFocus. Это не автозапуск; права администратора не нужны. После переноса папки запусти приложение из нового места, чтобы обновить ярлык.

Перед заменой папки новой версией заверши TGFocus через трей. Персональные настройки хранятся отдельно от папки программы.

**Известное ограничение v0.1.0:** если первоначальное подключение не удалось, например при входе в Windows до появления сети, кнопка переподключения может снова потребовать API-данные. После восстановления сети заверши TGFocus через трей и запусти заново: сохранённые ключи и сессия загрузятся автоматически. Повторное подключение без ввода ключей исправлено в исходниках после этого выпуска; опубликованный архив v0.1.0 не заменялся.

### Запуск при входе в Windows

По умолчанию автозагрузка выключена. После первого успешного подключения Telegram приложение один раз предложит включить её; галочка в предложении снята. Нажатие «Готово» без галочки и «Не сейчас» оставляют автозагрузку выключенной.

Позже открой **Обзор → Запуск вместе с Windows → Добавить TGFocus в автозагрузку Windows**. TGFocus создаёт только свой `TGFocus.lnk` в пользовательской папке автозагрузки, полученной через Windows Shell API. Прав администратора не требуется. При входе он запускается с `--autostart` в трее, без окна настроек, с сохранёнными правилами и состоянием фильтра. Если TGFocus уже работает, повторный фоновый запуск тихо завершается.

Кнопка **«Открыть автозагрузку Windows»** открывает **Параметры → Приложения → Автозагрузка**. Windows может отдельно запретить запуск TGFocus: галочка в приложении означает наличие его ярлыка, а не подтверждение системного разрешения. Приложение не меняет этот запрет и не восстанавливает запись, удалённую пользователем. Для обновления показанного состояния есть отдельная кнопка в «Обзоре».

После переноса portable-папки запусти нужную копию вручную и нажми **«Обновить путь к этой копии TGFocus»**. Это явное действие: при обычном запуске приложение не переписывает автозагрузку. Перед удалением папки сними галочку в TGFocus; это удалит только его собственный ярлык автозагрузки. Ярлык с чужим идентификатором не перезаписывается и не удаляется.

Для portable EXE используется штатная папка Startup и ShellLink. Системный `StartupTask.RequestEnableAsync` требует пакета и manifest-расширения, поэтому диалог согласия здесь принадлежит TGFocus. Реальный запуск после выхода/входа и отображение в системном списке нужно проверить на пользовательской Windows; CI проверяет создание, чтение, повторное включение без перезаписи и удаление ярлыка в изолированной временной папке.

### Если Chrome блокирует архив как опасный

Это отдельная проверка загрузки Chrome, а не то же самое, что окно SmartScreen при запуске. По одной надписи нельзя установить причину или считать срабатывание ложным. Не отключай защиту ради установки. Для диагностики нужны полный текст причины в Chrome (`Ctrl+J`) и, если появилась запись в **Безопасность Windows → Защита от вирусов и угроз → Журнал защиты**, название угрозы. Ключи Telegram, сессию и переписку присылать не нужно.

Каждая новая Windows-сборка в CI перед публикацией проходит проверку Microsoft Defender с обновлением баз. В **Actions → Windows build and checks → Run workflow** сопровождающий также может указать `scan_run_id` — числовой ID прежней Windows-сборки. Отдельная проверка скачает именно её артефакт, сверит SHA-256 внутреннего ZIP, запишет хеши распакованных файлов и просканирует архив и содержимое Microsoft Defender. Приложение во время сканирования не запускается, настройки защиты не меняются, автоматическая отправка образца стороннему сервису не выполняется. Без доступного Defender проверка завершится ошибкой, а не отчётом об отсутствии угроз.

Отчёт `TGFocus-Windows-security-report` содержит версии движка/баз, вывод сканера, его справку, код завершения и список файлов. Успешный результат означает только отсутствие обнаружений этой проверкой Defender; он не отменяет независимый вердикт Chrome и не гарантирует безопасность. Google различает [опасные и малоизвестные загрузки](https://github.com/chromium/chromium/blob/main/components/download/public/common/download_danger_type.h); доступные способы пересмотра описаны в [официальном FAQ Chromium](https://github.com/chromium/chromium/blob/main/docs/security/faq.md#how-can-i-appeal-a-safe-browsing-warning).

Для сравнения в **Run workflow** доступен флаг `compare_icons` (поле `scan_run_id` оставь пустым). Один Windows-сервер последовательно собирает и проверяет два пакета из одних исходников и в одном окружении: `TGFocus-Windows-icons-custom` с ICO внутри обоих EXE и `TGFocus-Windows-icons-none` без иконок внутри EXE. Отдельные PNG/ICO для окна и уведомлений входят в оба пакета. Это диагностические варианты, а не способ обойти защиту или подтверждение ложного срабатывания. Для локальной сборки второго варианта есть `python source/Windows/build.py --without-exe-icons`. При проверке в Chrome сохрани вердикт Safe Browsing для каждого архива; перед запуском другого варианта заверши предыдущий через трей и распакуй пакеты в разные папки.

## Подключить Telegram

1. Получи собственные **API ID** и **API Hash** на https://my.telegram.org/apps . Не отправляй их автору или в issue.
2. Введи их в настройках и подключись. Для QR-входа открой Telegram на телефоне → **Настройки → Устройства → Подключить устройство**. Подтверди вход. При необходимости введи пароль двухэтапной аутентификации.
3. Настрой важных людей, ключевые слова, исключения групп/каналов, упоминания и ответы. Для проверки локальных правил вход в аккаунт не обязателен.
4. Включи главный фильтр. Попроси собеседника прислать подходящее сообщение и проверь настоящий баннер Windows.

Чаты и темы форумов, заглушённые в Telegram, остаются тихими. Приложение не пишет в чаты, не отмечает сообщения прочитанными и не загружает вложения. Уже запущенный обычный Telegram продолжает работать независимо.

Уважение mute Telegram **всегда включено**, отдельного переключателя нет. Заглушённый чат или тема не проходят даже как важный собеседник, упоминание, исключение или подходящее ИИ сообщение; текст такого сообщения не отправляется ИИ. Неизвестные настройки уведомлений также приводят к отказу. Журнал «Последние решения» показывает и отклонённые сообщения: строка в нём не означает, что TGFocus отправил баннер. Причина «не разрешены правилами TGFocus» относится к локальным правилам, а «уведомления чата выключены в Telegram» — к mute самого Telegram.

## Уведомления и авто-режим

По умолчанию фильтр переключается вручную. Если обычный Telegram тоже показывает баннеры, возможны дубли.

Для автоматизации открой **Обзор → Автоматизация — эксперимент** и включи **«По режиму «Не беспокоить» Windows (WNF)»**, затем разреши главный фильтр. Теперь доставка TGFocus разрешена только при активном «Не беспокоить». На новой установке автоматизация выключена.

При включении автоматики приложение подписывается на изменения через **Windows Notification Facility (WNF)** и сразу читает текущее состояние. После выхода из сна и перед доставкой разрешённого баннера состояние читается ещё раз, чтобы не использовать устаревшее значение. Постоянного опроса нет. Главный выключатель останавливает доставку независимо от состояния Windows.

Это чтение внутреннего, недокументированного состояния Windows: администратор и платный сертификат для него не нужны, но обновление ОС может нарушить совместимость. При недоступном интерфейсе, неизвестном значении или ошибке доставка в авто-режиме приостанавливается. Приложение не включает и не выключает системный DND. **Сеанс Focus не используется как замена состоянию «Не беспокоить».** При проблемах выключи автоматику и используй ручной фильтр.

Настрой уведомления Windows один раз:

1. Выключи системный **«Не беспокоить»**, оставив TGFocus запущенным. В приложении открой **Обзор → Уведомления Windows** и нажми **«Тестовое уведомление Windows»**. Тест не зависит от правил фильтра и не читает Telegram.
2. Нажми **«Открыть параметры уведомлений Windows»**. Найди **TGFocus**, включи уведомления и показ баннеров. Если параметры Windows были открыты до запуска TGFocus, закрой их и открой заново.
3. В **Система → Уведомления → Задать приоритетные уведомления → Добавить приложения** выбери **TGFocus**. Обычный Telegram туда не добавляй, иначе возможны дубли.
4. Включи **«Не беспокоить»** и повтори тест TGFocus. Проверь именно видимый баннер, а не только запись в центре уведомлений.

Если TGFocus нет в списках, в «Обзоре» нажми **«Восстановить регистрацию TGFocus»**, повтори тест с выключенным DND и заново открой параметры Windows. Не запускай приложение от администратора. Программа показывает доступный статус разрешений, но сама не включает системные уведомления и не меняет список приоритетных приложений. Названия пунктов зависят от версии Windows. Определение DND и принятие запроса Windows не подтверждают, что баннер действительно появился.

Для нового переносимого приложения Windows иногда ещё не создала профиль уведомлений: чтение разрешений возвращает `ERROR_NOT_FOUND` (`0x80070490`). Только в этом случае TGFocus пробует отправить первое уведомление, чтобы Windows могла создать профиль. Явные запреты, другие ошибки и поведение пакетных приложений этим исключением не меняются. Если тест не проходит, скопируй точный текст ошибки с кодом Windows из TGFocus — он различает чтение разрешений, формирование/отправку и последующий отказ Windows. В диагностике не показываются текст сообщений, ключи и системные пути.

Проверь на своём компьютере ручное включение и выключение «Не беспокоить», запуск TGFocus при уже активном режиме, включение по расписанию, выход из сна и отсутствие дублей. При отдельном сеансе Focus ориентируйся на фактический переключатель DND. Не полагайся на авто-режим для срочной связи до этой проверки.

## Необязательный ИИ

Поддерживаются OpenRouter и DeepSeek. Сначала добавь конфиденциальные диалоги в исключения ИИ, затем укажи провайдера, модель, собственный ключ и порог важности. По умолчанию внешняя обработка выключена. Бесплатность модели/лимиты определяет провайдер; веб-чат DeepSeek и API имеют разные условия.

Внешнему провайдеру отправляются первые 4000 символов подходящего текста, без добавления имён, ID, истории и файлов. Сам текст может содержать личные данные. Исключённые чаты используют локальные правила. При ошибке/лимите действуют обычные ключевые слова; при сбое подключения появляется беззвучное уведомление без повторов на каждое сообщение. Подробности: [AI.ru.md](AI.ru.md).

## Хранение данных

Настройки и секреты находятся в `%LOCALAPPDATA%\TGFocus` (тесты используют изолированный каталог). API-ключи и сессия зашифрованы Windows DPAPI для текущей учётной записи; в обычный JSON правил они не записываются. Код входа и пароль двухэтапной аутентификации не сохраняются. Зашифрованный файл не является переносимой резервной копией для другого пользователя/компьютера.

Журнал решений ограничен и хранится в памяти без текста переписки. Баннеры с разрешённым предпросмотром могут сохраняться самим Windows в центре уведомлений. Во сне и при закрытом приложении обработка не выполняется.

## Тестовые сборки до релиза

Для проверки новых изменений открой **Actions → Windows build and checks**, выбери успешный запуск нужной ветки и скачай **TGFocus-Windows-test-x64** (нужен вход в GitHub). Распакуй артефакт, затем находящийся внутри `TGFocus-Windows-x64.zip`. Эти архивы не являются опубликованными релизами. Перед запуском заверши предыдущую копию через трей; настройки пользователя общие.

## Сборка из исходников

Нужна **Windows x64 и Python 3.13 x64**. Из корня репозитория:

```powershell
py -3.13 source/Windows/build.py
```

Скрипт создаёт отдельное окружение в `source/Windows/.build`, устанавливает закреплённые зависимости, запускает совместимые тесты, упаковывает оба EXE, проверяет автономный worker и запуск GUI с изолированными данными. Итог — `dist/TGFocus-Windows-x64.zip` и SHA-256 рядом. Сборка Windows EXE на macOS/Linux этим скриптом не поддерживается.

CI не входит в Telegram, не использует реальные API-ключи и не отправляет сообщения провайдерам ИИ. Он проверяет программную интеграцию, сохранение тестовых секретов DPAPI, запуск окон и настоящий Windows-ярлык с чтением его идентификатора обратно из изолированной папки. В готовом EXE проверяется также формирование трёх настоящих объектов WinRT: обычное уведомление, беззвучный сбой ИИ с обработчиком нажатия и ссылка Telegram; финальный вызов системного показа перехватывается тестом. Появление приложения в интерфейсе параметров, видимые баннеры, SmartScreen, QR-вход и реальное переключение DND требуют ручной проверки на Windows.

Пакет включает лицензии компонентов в `Licenses`, в том числе полные LGPLv3/GPLv3 и upstream-уведомления Qt/PySide/Shiboken в `Licenses/Qt-notices`. Используются PySide6 Essentials/Qtbase; необязательные PDF/SVG/WebP/TIFF-плагины не включаются. Python и динамические библиотеки остаются отдельными файлами переносимой папки. `Source` содержит исходники Windows-оболочки, worker и скрипты пересборки. Полные исходники Qt не входят в архив: точные ссылки на upstream-релиз 6.12.0 и инструкция замены совместимых LGPL-библиотек приведены в `Licenses/Qt-notices/README.md`.
